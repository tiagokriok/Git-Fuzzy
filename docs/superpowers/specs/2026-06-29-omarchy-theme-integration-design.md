# Omarchy Theme Integration Design

## Summary

Add a theme system to `gitf` so the TUI can follow the active Omarchy theme. The implementation should support automatic Omarchy detection, a cache generated by a CLI command, manual theme files, and live theme refresh while the Bubbletea UI is open.

## Goals

- Make `gitf` follow the current Omarchy theme by default on Omarchy systems.
- Preserve a safe default theme for non-Omarchy systems.
- Add a generic theme layer so future sources are not tightly coupled to Omarchy.
- Support manual theme files.
- Let Omarchy hooks sync a `gitf` theme cache through a stable command.
- Update the main TUI and setup wizard when the theme changes while open.

## Non-goals

- Do not add a setup wizard step for theme selection in this version.
- Do not force panel backgrounds by default.
- Do not add a filesystem watcher dependency in this version.
- Do not support shorthand hex colors like `#RGB` in this version.

## User behavior

### Config

`gitf` supports a new optional config object:

```json
"theme": {
  "mode": "auto"
}
```

Supported modes:

- `auto`: default for old configs. Try Omarchy cache, validate it against the current Omarchy theme name, reload Omarchy if stale, and fall back to the built-in theme if unavailable.
- `default`: always use the built-in theme.
- `omarchy`: explicitly use Omarchy. If Omarchy fails, use the built-in theme and show a discreet warning.
- `file`: load a user-specified theme file from `path`.

Invalid or missing mode values normalize to `auto`.

Example manual theme config:

```json
"theme": {
  "mode": "file",
  "path": "~/.config/gitf/my-theme.json"
}
```

### CLI command

Add:

```bash
gitf theme sync-omarchy
```

Behavior:

- Reads the current Omarchy theme from `~/.config/omarchy/current/theme` (colors come from `colors.toml` inside that directory; the theme name lives one level up at `~/.config/omarchy/current/theme.name` in real Omarchy layouts, with a fallback to `~/.config/omarchy/current/theme/theme.name` for legacy/test setups).
- Writes `~/.config/gitf/theme.json`.
- Prints a success message with the theme name and cache path.
- If Omarchy files are missing or invalid, prints an error to stderr and exits non-zero.

Example hook line:

```bash
gitf theme sync-omarchy >/dev/null
```

### Live theme refresh

The main TUI and setup wizard poll for theme changes every 2 seconds using Bubbletea ticks.

When a change is detected:

- Reload the theme.
- Rebuild Lipgloss styles.
- Re-render the UI.

No live file watcher dependency is added.

## Theme model

Use a semantic palette in code. The UI should not reference Omarchy key names directly.

Semantic colors:

- `accent`
- `foreground`
- `muted`
- `border`
- `selection`
- `success`
- `warning`
- `danger`
- `info`
- `branch`
- `stash`
- `renamed`
- `copied`
- `untracked`

Omarchy mapping:

- `accent`: `accent`, fallback `color4`
- `foreground`: `foreground`
- `muted`: `color7`
- `border`: `color8`
- `selection`: `selection_background`, fallback `accent`
- `success`: `color2`
- `warning`: `color3`
- `danger`: `color1`
- `info`: `color6`
- `branch`: `color2`
- `stash`: `color5`
- `renamed`: `color5`
- `copied`: `color6`
- `untracked`: `color6`

Only `#RRGGBB` colors are accepted. Missing or invalid colors are ignored and filled from the built-in default theme.

## Cache and file formats

### Full cache format

`~/.config/gitf/theme.json`:

```json
{
  "source": "omarchy",
  "name": "Tokyo Night",
  "synced_at": "2026-06-29T01:23:45Z",
  "palette": {
    "accent": "#7aa2f7",
    "foreground": "#a9b1d6",
    "muted": "#787c99",
    "border": "#444b6a",
    "selection": "#7aa2f7",
    "success": "#9ece6a",
    "warning": "#e0af68",
    "danger": "#f7768e",
    "info": "#449dab",
    "branch": "#9ece6a",
    "stash": "#ad8ee6",
    "renamed": "#ad8ee6",
    "copied": "#449dab",
    "untracked": "#449dab"
  }
}
```

### Simple file format

Manual `file` themes may also use a flat palette:

```json
{
  "accent": "#7aa2f7",
  "foreground": "#a9b1d6",
  "success": "#9ece6a"
}
```

Both formats are accepted for `mode: "file"`. Partial palettes are merged with defaults.

## Architecture

### `internal/config`

Add:

```go
type ThemeConfig struct {
    Mode string `json:"mode,omitempty"`
    Path string `json:"path,omitempty"`
}
```

Add to `Config`:

```go
Theme ThemeConfig `json:"theme,omitempty"`
```

Provide helpers to normalize missing or invalid mode values to `auto`.

### `internal/theme`

Create a new package for theme loading and caching.

Suggested API:

```go
type Palette struct { ... }
type Theme struct { ... }
type Warning struct { Message string }

func Default() Theme
func Load(cfg config.ThemeConfig) (Theme, *Warning)
func LoadOmarchy() (Theme, error)
func LoadFile(path string) (Theme, error)
func SyncOmarchy() (ThemeCache, error)
```

Responsibilities:

- Parse Omarchy `colors.toml` with a small parser for `key = "#RRGGBB"`.
- Read Omarchy theme name from `theme.name`. In real Omarchy layouts the file is a sibling of the `theme/` directory (`current/theme.name`); a fallback to `current/theme/theme.name` preserves legacy/test layouts.
- Read/write `~/.config/gitf/theme.json`.
- Validate cache by comparing cached Omarchy name with current Omarchy `theme.name` (resolved with the same parent-first, legacy-fallback lookup as the live loader).
- Auto-heal stale Omarchy cache silently when possible.
- Merge partial palettes with defaults.

### `cmd/gitf/main.go`

Add Cobra subcommand:

```bash
gitf theme sync-omarchy
```

For TUI flows:

- Load theme before `ui.Run`.
- Load theme before `ui.RunSetup`.
- Pass theme and optional warning into UI/setup constructors.

### `internal/ui`

Add `internal/ui/styles.go`:

```go
type Styles struct { ... }
func NewStyles(t theme.Theme) Styles
```

Replace hardcoded `lipgloss.Color("...")` calls in `ui.go` and `setup.go` with semantic styles or semantic colors from `Styles`.

The main model and setup model should store:

- current `theme.Theme`
- current `Styles`
- optional theme warning/status text
- last observed theme state for polling

Polling:

- Use `tea.Tick(2*time.Second, ...)`.
- Re-check relevant cache/theme metadata.
- Reload and rebuild styles if changed.

## Error handling

- `auto`: silently falls back to default if Omarchy is unavailable.
- `omarchy`: falls back to default and shows a discreet warning in the TUI/setup.
- `file`: falls back to default and shows a discreet warning if the file cannot be read or parsed.
- `gitf theme sync-omarchy`: prints a clear stderr error and exits non-zero on failure.
- Invalid color values are ignored and replaced by defaults.

## Testing plan

### Config tests

- Missing `theme` resolves to `auto`.
- Empty mode resolves to `auto`.
- Invalid mode resolves to `auto`.
- Valid modes are preserved.

### Theme package tests

- Parse valid Omarchy `colors.toml` lines.
- Ignore comments, blank lines, unknown keys, and invalid hex values.
- Map Omarchy colors to semantic palette.
- Merge partial palettes with default colors.
- Load full cache JSON.
- Load simple flat JSON.
- Detect stale cache by theme name mismatch.
- Sync Omarchy writes full cache with metadata.

### UI tests

- `NewStyles(theme.Theme)` maps semantic colors to Lipgloss styles.
- Theme warning text can be rendered in footer/status.
- Theme polling helper detects changed theme state.

Avoid brittle full-screen snapshot tests.

## Acceptance criteria

- Existing configs use `theme.mode = auto` behavior without modification.
- On Omarchy, `gitf` uses the active Omarchy colors by default.
- Non-Omarchy systems keep a usable built-in theme.
- `gitf theme sync-omarchy` writes `~/.config/gitf/theme.json` and reports success.
- Manual `file` mode accepts full and flat JSON theme formats.
- Main TUI and setup wizard update theme while open within the 2s polling interval.
- UI uses semantic theme colors instead of scattered hardcoded Lipgloss colors.
- Relevant config/theme behavior has automated tests.
